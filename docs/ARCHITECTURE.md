# RoomBap 구조

## 실행 경로

RoomBap은 브라우저 화면과 같은 출처의 JSON API로 구성됩니다. `scripts/preview-local.mjs`는 Node.js 기본 HTTP 서버로 `server/page.html`, `public/`의 파일, `server/api.mjs`의 API를 제공합니다. 기본 실행에는 외부 npm 패키지 설치가 필요하지 않습니다.

Sites / Cloudflare Workers 환경에서는 `worker/index.ts`가 같은 페이지·API를 제공하고 나머지 요청을 기존 Vinext 처리기로 전달합니다. 관련 프레임워크 설정과 잠금 파일은 그대로 보관합니다. 저장소의 기본 안내는 별도 호스팅 계정 없이 실행할 수 있는 Node.js 서버를 기준으로 합니다.

## 화면 구성

- `server/page.html`: 메인 화면·설문·메뉴 상세 창·AI 팝업의 HTML과 스크립트 연결.
- `public/app.js`, `style.css`: 매장 탐색, 설문, 메뉴 옵션, 장바구니, 시연 주문과 기존 화면 렌더링.
- `public/catalog-data.js`: 공통 카탈로그에서 생성한 실제 실행용 매장·메뉴·사진 연결 데이터. 원본 대조용 데이터 파일들과 구분하여 한 가지 카탈로그만 로드합니다.
- `public/ai-bridge.js`: 화면의 선택 취향과 메뉴 연결을 AI UI에 제공.
- `public/ai-client.js`: 같은 출처의 API 요청, 제한 시간·취소·카탈로그 버전 확인.
- `public/ai-ui.js`: 음식 요청, 저장한 취향 추천, 유행 음식 질문, 관련 메뉴와 근거 표시.
- `public/ai-dialog.js`, `ai-dialog.css`: 오른쪽 아래 런처, 중앙 팝업, 키보드 초점과 닫기 동작.
- `public/cart-order-fixes.js`, `catalog-cart-guard.js`: 수정 확정 전 장바구니 보존, 옵션 병합·수량 검증, 주문번호·중복 실행 방지, 바뀐 카탈로그의 주문 차단.
- `public/privacy-notices.js`: 영어·일본어·중국어 설문·AI 입력·도움말 안내.

원본 화면 파일의 해시와 메인 HTML 구조를 `docs/design-baseline.json`으로 확인합니다. `public/`은 Git의 줄바꿈 변환을 적용하지 않아 운영체제가 달라도 보관한 원본 바이트와 검증 결과를 유지합니다.

## AI 음식 추천

1. 브라우저에서 요청한 질문·저장 취향·호텔 ID·결과 개수를 API로 보냅니다.
2. 질문이 있으면 Claude가 음식 종류·맛·기본 가격·제외 조건 등을 구조화합니다. 저장 취향은 별도로 서버에서 검증·병합합니다.
3. 서버가 메뉴·매장·시연 배달 경로·필수 옵션·예산·식이 조건을 확인합니다. 알 수 없는 재료·안전성·인증 정보를 임의로 보완하지 않습니다.
4. 특정 요리나 세부 특징은 Claude가 후보 메뉴의 실제 필드를 근거로 대조하고 서버가 메뉴 ID와 인용 문자열을 검사합니다.
5. 지원 태그의 임베딩을 조합한 검색 벡터와 메뉴 벡터의 코사인 유사도, 태그 점수로 순위를 정합니다. 벡터 점수 65%와 태그 점수 35%를 반영합니다. 임의의 요청 문장에 전체 임베딩 인코더를 실시간 실행하는 방식은 아닙니다.
6. 화면에서 확인할 수 있는 메뉴 ID·이름·가격이 일치할 때 해당 메뉴의 옵션 창으로 연결합니다.

제약이 표현 불가능하거나 메뉴 정보로 확인되지 않으면 보류·빈 결과·오류를 반환합니다. 오류를 가짜 추천으로 대체하지 않습니다.

## 한국 유행 음식 설명

등록된 음식 주제의 별칭과 미리 만든 벡터를 이용하여 근거 자료를 선택합니다. Claude에 질문·요청 언어·허용된 근거를 전달하고, 별도의 모델 호출로 설명의 관련성·인용·언어를 대조합니다. 서버는 인용 ID와 근거에 실제로 존재하는 문자열도 검증합니다. 근거가 충분하지 않으면 답변을 보류합니다. 현재 인기 순위를 추적하거나 외부 사이트를 실시간 수집하지 않습니다.

## 카탈로그와 검색 데이터

`data/catalog.json`과 `data/menu-id-registry.json`이 편집 원본입니다. 빌드 도구는 브라우저·API용 데이터와 검색 벡터 입력을 생성합니다. MiniLM 임베딩은 Python 도구로 미리 준비하며, 생성한 벡터를 소스와 함께 보관하므로 일반 실행에서 모델을 내려받을 필요가 없습니다.

브라우저·서버·벡터는 같은 카탈로그 버전을 사용합니다. 서버는 오래된 요청을 차단하고, 브라우저도 버전이 다른 성공 응답을 표시하지 않습니다.

## 저장·외부 통신

설문·저장 매장·장바구니·시연 주문은 `sessionStorage`를 사용합니다. 서버 API는 같은 요청의 결과를 잠시 메모리에서 재사용합니다. Claude 키는 실행 환경에서만 읽고, AI 호출은 서버가 수행합니다. 프론트엔드 지도·폰트·출처 링크 등은 각 구성의 외부 자료를 사용합니다.

실제 주문·결제 처리, 회원 계정, 호텔 투숙 인증용 데이터베이스는 연결하지 않습니다.
