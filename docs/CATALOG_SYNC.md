# 메뉴 데이터 동기화 — 1단계

기준은 팀원 사이트에서 확인하여 이 프로젝트에 보관한 2026-10-29 버전입니다. 매장 50개와 메뉴 144개를 사용합니다. 실행할 때마다 외부 사이트를 수집하는 방식이 아니며, 앞으로는 이 프로젝트의 공통 원본을 버전 관리합니다.

## 한 곳에서 관리하는 원본

- `data/catalog.json`: 매장·메뉴·가격·옵션·시연 품절 상태·최소금액·배달비·사진 연결·재료와 식이 참고 정보·AI 검색 태그의 편집 원본입니다.
- `data/menu-id-registry.json`: 현재 메뉴 ID와 음식명의 연결, 폐기된 ID를 보관합니다. 기존 ID는 모두 유지했습니다. `reference-0`처럼 이름에 순번이 남아 있어도 현재는 고정된 ID입니다. 순서를 바꾸어 새로 생성하지 않습니다.
- `public/catalog-data.js`: 공통 원본에서 자동 생성하는 화면용 데이터입니다.
- `server/data/frontend_catalog.json`: 같은 원본에서 자동 생성하는 AI용 데이터입니다.
- `server/data/vectors.json`: 같은 버전의 메뉴와 검색 태그를 기준으로 생성하는 다국어 검색 벡터입니다.

자동 생성 파일은 직접 수정하지 않습니다. 공통 원본을 수정한 뒤 생성 명령을 실행합니다. 원본 화면의 렌더링 코드 `public/app.js`, `style.css`, 사진 파일은 수정하지 않았습니다. 이전 데이터 스크립트 6개는 원본 대조를 위해 보존했지만 현재 HTML에서 실행하지 않습니다. 화면은 `catalog-data.js`만 데이터 원본으로 사용합니다.

## 이번 동기화 결과

기존 AI 데이터 120개에서 새 메뉴 27개를 추가하고, 팀원 사이트 버전에서 사라진 메뉴 3개를 제거했습니다. 기존 메뉴 중 계속 존재하는 117개의 ID를 유지했습니다.

삭제된 3개는 `place-dessert-4-bingsu`, `place-dessert-4-fruit-tart`, `place-dessert-4-soft-serve`입니다. 현재 해당 매장의 메뉴는 `place-dessert-4-dubai-cookie`이며 기록된 기본 가격은 6,800원입니다. 삭제 메뉴의 검색 벡터도 제거했습니다. 새 매장 10개와 메뉴의 기본 가격·옵션·배달비·최소 주문금액을 함께 연결했습니다.

새 메뉴의 검색 태그는 음식명과 제공된 정보로 구분합니다. 샐러드 매장의 피자를 샐러드로 분류하거나, Halal 카테고리의 메뉴를 인증 메뉴로 간주하지 않습니다. 샐러드·포케·피자·카레 등의 검색 태그와 벡터를 추가했습니다. 두쫀쿠는 등록된 음식 소개 주제와 메뉴 ID를 연결하여 관련 메뉴 버튼으로 찾을 수 있습니다.

## 정보 확인 수준

원본의 재료 목록·알레르기 목록·식이 표기·출처·확인일을 유지합니다. 다만 음식 종류를 설명하는 참고 목록이나 비어 있는 목록은 완전한 성분 선언이 아닙니다. 따라서 현재 AI의 제한 조건 검증에서는 `ingredients_status`, `allergens_status`, `vegetarian_status`를 여전히 `unknown`으로 취급합니다. 원본의 식이 표기는 `source_dietary`, 알레르기 표기는 `source_allergen_status`로 별도 보존합니다.

이번 작업에서 돼지고기 제외·비건·할랄 등의 기존 추천 보류 정책을 완화하지 않았습니다. 이 지원 범위 개선은 별도 단계입니다. 가격은 기본 메뉴 가격이며, 필수 옵션 추가금·배달비·장바구니 최소 주문금액은 별도 필드로 유지합니다. 실제 영업·재고·배달·결제를 검증하거나 실행하는 기능은 아닙니다.

## 메뉴를 수정하는 순서

1. `data/catalog.json`에서 메뉴의 이름·가격·옵션 등을 수정합니다. 기존 음식을 유지할 때는 ID를 유지합니다. 새로운 음식에는 새 ID를 발급하고 ID 등록부에 추가합니다. 이름 정정은 등록부의 대응 이름도 함께 수정합니다. 폐기 ID는 새 음식에 재사용하지 않습니다.
2. `npm run catalog:build`로 화면·AI 데이터와 벡터 생성 입력을 갱신합니다.
3. 검색 벡터를 갱신합니다. 처음 준비할 때만 Python 환경에서 `pip install -r requirements-catalog-embeddings.txt`를 실행합니다.

```powershell
python scripts/prepare-catalog-embeddings.py --cache-dir .cache/embeddings --download
```

공개 모델을 이미 준비했다면 `--download`를 제외합니다. 모델 캐시와 가상환경은 Git에서 제외되며, 생성된 벡터는 코드와 함께 보관하므로 일반 실행에는 Python 모델이 필요하지 않습니다.

4. `npm run catalog:check`, `npm test`, `npm run check:design`을 실행합니다. 미리보기 서버를 다시 시작하고 화면을 새로고침합니다.

## 충돌 방지

- 화면·AI·벡터는 같은 카탈로그 버전을 기록합니다. 생성물이 오래됐으면 빌드 또는 로컬 미리보기 시작 시 검증이 실패합니다.
- 브라우저는 AI 요청에 카탈로그 버전을 함께 보냅니다. 서버와 버전이 다르면 결과를 섞어 보여주지 않고 새로고침을 안내합니다. 오래된 성공 응답도 화면에서 차단합니다.
- 없는 메뉴, 다른 음식에 재사용된 ID, 중복 ID, 잘못된 옵션 참조는 검증에서 차단합니다.
- 필수 옵션을 선택할 수 없는 메뉴는 AI 추천 후보에서 제외합니다. 옵션별 가격과 품절 정보는 그대로 유지합니다.
- 저장된 장바구니에 삭제 메뉴나 바뀐 가격·옵션이 있으면 주문 진행을 막고 다시 선택하도록 기존 토스트로 안내합니다. 장바구니 내용은 자동 삭제하지 않습니다. 과거 모의 주문 기록은 변경하지 않습니다.

기존 공개 사이트는 변경하지 않았습니다. 이 결과는 Git 공유용 로컬 작업본에 반영했습니다.
