# 장바구니·주문 오류 수정 복원

팀원 전달본과 현재 원본 디자인을 유지하면서, AI 통합본에서 보완했던 장바구니 수정 취소 및 주문번호 처리를 복원했습니다. 기존 공개 사이트는 변경하지 않았습니다.

## 동작

- 옵션 수정 화면을 열어도 기존 장바구니를 삭제하거나 저장하지 않습니다. 수정 중인 옵션과 수량은 임시 값입니다.
- X·Esc로 닫거나 수정 중 새로고침하면 마지막으로 저장한 상품·옵션·수량이 유지됩니다.
- 확정할 때만 기존 줄을 교체하며, 수량을 이전 수량에 다시 더하지 않습니다. 가격과 총액·최소 주문금액은 기존 화면 계산식으로 갱신합니다.
- 수정한 옵션이 이미 있는 다른 줄과 같아지면 수량을 합칩니다. 합계가 기존 제한인 10개를 초과하면 임의로 잘라내거나 저장하지 않고 안내합니다. 수량을 줄여 다시 저장할 수 있습니다.
- 수정 중인 줄이 없어졌거나 메뉴·옵션이 더 이상 유효하지 않으면 저장을 차단하고 기존 내용을 보존합니다.
- 신규 모의 주문은 `RB-`와 전체 UUID로 주문번호를 생성합니다. 기존 주문번호와 겹치면 재시도하며 생성에 실패하면 장바구니를 비우지 않습니다.
- 주문이 만들어져 장바구니와 주문 입력이 초기화된 뒤에는 이전 결제 버튼의 중복 콜백을 무시합니다. 기존 주문 기록과 상태는 유지합니다.

수정 코드는 `public/cart-order-fixes.js`에 분리했습니다. 원본 `public/app.js`, 스타일, 음식 사진, 렌더링 HTML은 변경하지 않았습니다. `server/page.html`에서 원본 앱을 불러온 직후 동작 보완 코드를 적용합니다. 메뉴 동기화 단계에서 추가한 가격·품절·삭제 메뉴 검증도 함께 유지합니다.

## 검증

2026-10-30 검증 결과: 전체 자동 검사 241개 통과, 실제 브라우저 동작 11개 통과, 처리되지 않은 화면 오류 0개입니다. 원본 디자인 파일 153개와 메인 화면 구조가 그대로 유지되며, 화면·서버의 메뉴 144개가 동일한 버전임을 확인했습니다.

브라우저 기록은 [검증 보고서](cart-order-review/browser-report.json), [모바일 주문 완료 화면](cart-order-review/order-mobile.png), [최소 주문금액 화면](cart-order-review/minimum-order-mobile.png)에서 확인할 수 있습니다.

`tests/cart-order.test.mjs`는 수정 취소, 확정, 동일 옵션 합치기, 수량 제한, 오래된 수정 상태, 잘못된 옵션, 주문번호 충돌·생성 실패 및 중복 결제 콜백을 검증합니다. 실행 방법은 다음과 같습니다.

```powershell
node --test server/*.test.mjs tests/*.test.mjs
node scripts/check-design-baseline.mjs
node scripts/catalog-check.mjs
```

브라우저에서는 원본 메뉴 화면을 이용해 X·Esc·새로고침으로 수정 취소, 옵션·수량 확정, 항목 합치기, 최소금액 재계산, 모의 주문과 상태 저장을 확인합니다. 이름·전화번호는 테스트용 합성값을 사용합니다. 실제 결제·식당 주문 전송은 처리하지 않습니다.
